# D-O15 — definição e implementação

## Definição canônica

D-O15 é **otimização inteligente**: encontrar a representação/processamento
mais eficiente possível **sem perder significativamente o resultado
necessário**.

> Otimização **NÃO** significa "reduzir qualidade".

Não se faz claim de otimização sem medição. D-O15 **mede** (custo real),
**analisa** (pressão/gargalo), **decide** (por sistema, por relevância e
criticidade), **adapta** (detalhe, Hz, raio de materialização, hardware),
**prioriza** e **agenda** (scheduler), e controla **abstração/materialização**
preservando estado.

## Implementação

- **Perfis de hardware** (`HARDWARE_PRESETS`): low-end 4ms · mid 10ms ·
  high-end 25ms · workstation 60ms (orçamento por tick) + `detectHardware()`
  (heurística cpus/mem).
- **Profiler** sobre `PerfMeter`:
  - `pressure()` = fração do orçamento consumida (medição real);
  - `bottleneck()` = só reporta quando o orçamento é **efetivamente estourado**
    (evita falso positivo);
  - `memoryMB()`.
- **StrategyEngine.decide(specs, pressure)**:
  - `p < 0.5` → **full** (folga; permite promoção/re-materialização);
  - `0.5 ≤ p < 0.9` → escala contínua `1 − ((min(p,0.9)−0.5)/0.4)·0.55`
    (p=0.5→1.0, p=0.9→0.45); relevância < 0.5 agrava não-críticos;
  - `p ≥ 0.9` → não-críticos → `cached` (Hz 0); críticos → piso de 10% no
    minHz (**o mundo nunca morre**);
  - representação: `full ≥0.85 · coarse ≥0.4 · aggregate >0 · cached`;
    Hz = `baseHz·(granted/req)` clampa em `[minHz, baseHz]`.
- **AdaptiveScheduler**: ordem por prioridade; orçamento do perfil de hardware;
  mede o trabalho REAL via `PerfMeter`; **adiaga, não descarta**; relata
  `ran / deferred / notDue / usedMs / overBudget`.
- **Controle de materialização** (novo): a decisão do sistema `streaming`
  ajusta o **raio de materialização** do mundo — pressão alta encolhe a zona
  materializada (mais abstração, tick mais barato, MESMO resultado); folga
  restaura o raio configurado.
- **Hardware adaptativo**: `autoOptimize()` degrada/promove o perfil pela
  pressão medida (escada low-end→mid→high-end→workstation).

## O que D-O15 NÃO é

- Não é "baixar o gráfico". Com folga, ele devolve full (mesmo resultado).
- Não inventa gargalo: sem estouro medido, `bottleneck()` retorna nulo.
- Não descarta trabalho: defere para o próximo ciclo.
