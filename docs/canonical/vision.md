# UTS/UES — A VISÃO (registro canônico da correção fundamental)

> Esta é a **referência suprema** de arquitetura. Qualquer implementação,
> teste ou percentual só vale se servir a esta visão. Nada aqui substitui
> os prompts — registra e protege o que eles definem.

## As duas regras supremas

1. **NÃO SIMULAR A APARÊNCIA DA REALIDADE QUANDO PUDERMOS MODELAR A
   REALIDADE QUE PRODUZ ESSA APARÊNCIA.**
2. **NÃO OTIMIZAR DESTRUINDO A REALIDADE; OTIMIZAR A FORMA COMO A
   REALIDADE É REPRESENTADA, PRIORIZADA E MATERIALIZADA.**

## A cadeia canônica (única direção permitida)

```
REALIDADE
   ↓
MODELO CAUSAL / REPRESENTAÇÃO (RRW — fonte única da verdade)
   ↓
SIMULAÇÃO / ESTADO (processos: clima, água, fogo, vida, economia…)
   ↓
PERCEPÇÃO (o que o observador/agente realmente consulta agora)
   ↓
FRAME / ÁUDIO / INTERAÇÃO
   ↓
HARDWARE (inevitável, isolado atrás de interface própria)
```

O Renderer **não** é fonte da realidade. O áudio **não** é fonte. A física
**não** cria uma realidade separada. A IA **não** cria uma realidade
separada. Tudo converge para a MESMA arquitetura de realidade.

## UTS ≠ UES

- **UTS** = plataforma geral AI-first (infraestrutura, serviços, IA,
  ferramentas, apps, CreationProjects). Não precisa estar completa em todos
  os recursos para a UES estar completa.
- **UES** = engine de experiências dentro da UTS: mundos, jogos, simulações,
  aplicações, sistemas interativos — LITERALMENTE TUDO dentro das
  capacidades dela.
- Interface principal: `USUÁRIO → linguagem natural + anexos + contexto +
  serviços → Singularity AI/Core → interpretação → planejamento → execução
  → verificação → UES → experiência`. **A IA é a principal interface de
  criação.**

## Realidade como referência primária

Para cada fenômeno real relevante (matéria, espaço, tempo, luz, sombra,
atmosfera, clima, água, terreno, vegetação, fogo, fluidos, partículas, som,
acústica, movimento, forças, colisões, deformação, organismos, percepção,
comportamento, sociedade, economia, causalidade, crescimento, destruição,
ciclos naturais…), a pergunta é SEMPRE:

> **"Como a realidade faz isso?" — e só depois — "como representar isso
> computacionalmente?"**

## Técnicas computacionais ≠ ontologia

LOD, impostors, ray tracing, shaders, partículas são **mecanismos de
implementação/otimização** — nunca o fundamento. O céu não é "uma skybox";
a água não é "um shader"; a fumaça não é "partículas falsas"; o fogo não é
"uma textura"; o som não é "playback de arquivos". Se existe um fenômeno
representado, a técnica apenas o MATERIALIZA dentro do orçamento.

## Mundo vivo, não cena

O mundo muda, cresce, envelhece, sofre eventos, produz consequências; tem
clima, ciclos, organismos, agentes, sociedade, economia, recursos, memória,
causalidade. Árvore que cresce tem ESTADO. Tempestade tem CAUSAS.
Incêndio afeta o AMBIENTE. NPC age da PERCEPÇÃO/MEMÓRIA/ESTADO — nunca de
script.

## NMN = mente, não "NPC AI"

Necessidades → percepção → memória → relações → conhecimento → medo →
objetivos → decisão → ação → consequência → nova memória. Decisões surgem
do estado do agente e da realidade. IA externa ajuda a interpretar/criar;
não mantém a realidade viva sozinha.

## RealLife é transversal

"Real Life" não é um módulo: é o princípio de modelar os fenômenos reais e
conectá-los — ambiente, clima, luz, atmosfera, materiais, água, fogo,
fenômenos, ciclos, causalidade, comportamento — influenciando Renderer,
Physics, Audio, NMN, World e todos os sistemas.

## Escalas são realidade, não LOD

micro → objeto → organismo → indivíduo → grupo → sociedade → ambiente →
região → mundo. A cidade distante NÃO vira textura: continua **estado
causal** com menor granularidade; quando a atenção/necessidade aumenta,
materializa em maior detalhe SEM destruir continuidade (D-14/D-O15/
scheduler/percepção/streaming conectados).

## D-O15: aproximar realidade desejada ↔ recursos disponíveis

REALIDADE DESEJADA ↓ REALIDADE REPRESENTADA ↓ RECURSOS COMPUTACIONAIS.
Deferir / reduzir custo / priorizar / representar adaptativamente —
**preservando estado, causalidade e resultado observável**. A otimização
nasce da própria representação da realidade.

## Critério de "COMPLETO" (as 12 exigências)

Um sistema só está completo para o milestone quando:
1. implementação própria; 2. contrato/API próprio; 3. integra-se à
realidade da UES; 4. causalidade quando aplicável; 5. persistência quando
aplicável; 6. integração com D-O15 quando aplicável; 7. testes unitários;
8. testes de integração; 9. medição de desempenho; 10. demonstração real;
11. sem dependência desnecessária de engine externa; 12. **representa
corretamente o fenômeno que afirma representar, dentro do escopo
definido**.

## Objetivo final

Não é "uma engine parecida com Unreal feita pela UTS". É **uma plataforma
AI-first que constrói e executa experiências a partir da descrição humana,
usando uma engine (UES) baseada em uma representação computacional da
realidade** — a mais fiel possível dentro dos limites computacionais.

## Não destruir o que existe

Preservar o que funciona. **Evoluir** a arquitetura para que RRW, D-O15,
NMN, RealLife, Scheduler, Renderer, Audio, Physics, Persistence,
Singularity AI e UTS Platform converjam para esta visão única.
